# 提案写作规范

## 一、目的与适用范围

为提高实训基地提案的可读性、可评审性和可追溯性，参考量潮科技既有提案的常用结构，统一提案的基本信息、方案说明和待决议事项。

本文件为提案格式的建议规范，适用于制度、组织治理、流程、项目与业务类提案；具体内容可根据议题增减，不要求所有提案机械保留全部章节。正式约束力以组织审议结果为准。

## 二、命名与基本信息

1. 提案使用 Markdown（`.md`）格式。
2. 文档标题建议采用「YYYY年第XX周-提案X-提案名称」，周次和编号依据实际登记记录填写，不自行编造。
3. 文档开头注明提案人、提案日期及审议主体；尚未确认的字段明确标注「待确认」。
4. 参考资料应提供可核验的文件或链接，必要时注明与既有制度的关系。

## 三、标准结构

| 模块 | 内容 | 要求 |
| --- | --- | --- |
| 案由 | 背景、现存问题、提出目的 | 必填 |
| 提案内容 | 具体方案、适用范围、关键规则 | 必填 |
| 实施安排 | 责任人、步骤、期限、验收方式 | 按需 |
| 提请决议 | 需要审议组织批准或确定的事项 | 必填 |
| 附议与审议记录 | 反馈意见及处理情况 | 按需，可链接至独立评审记录 |
| 决议结果 | 决议日期、结论、后续执行信息 | 审议后补充 |
| 参考资料 | 相关制度、既有提案与依据 | 按需 |

提请决议应聚焦**尚待确定**的事项，不重复表决已经确定的前置要求。简单事项允许合并或省略可选模块，不为凑齐章节添加无关内容。

## 四、Markdown 格式

1. 文档名称使用一级标题（`#`），主要章节使用二级标题（`##`），必要的小节使用三级标题（`###`）。
2. 用完整、明确的文字描述责任与执行条件；避免用含糊表述代替可验证要求。
3. 优先使用段落和列表；仅在多项内容需要横向比较时使用表格。
4. 标题、编号、术语与链接在同一文件内保持一致；避免不必要的加粗和深层嵌套。
5. 提案写作格式不替代章程条款格式；涉及正式章程的正文另按仓库的 [章程写作规范](bylaw.md) 编写。

## 五、通用提案模板

复制以下代码块内容，按实际议题替换占位信息，并删除不适用的小节。

```markdown
# YYYY年第XX周-提案X-提案名称

提案人：姓名

提案日期：YYYY-MM-DD

审议主体：待确认

## 一、案由

说明背景、问题与提案目的。

## 二、提案内容

说明建议方案及适用范围。

### 2.1 核心方案

明确拟新增、调整或废止的事项及具体规则。

### 2.2 执行边界（按需）

说明适用对象、例外情形及与既有规则的衔接。

## 三、实施安排（按需）

说明执行责任、关键步骤、时间节点与验收方式。

## 四、提请决议

1. 是否同意本提案提出的核心方案？
2. 尚待审议确认的具体标准、职责或执行问题是什么？

## 五、附议与审议记录（按需）

记录意见、修改结论，或附独立评审记录链接。

## 六、决议结果（审议后填写）

- 决议日期：待定
- 决议结论：待定
- 责任人：待定
- 后续记录：待补充

## 七、参考资料（按需）

- [资料名称](链接)
```

## 六、参考依据

- 量潮科技历年提案的通用结构归纳（历史样本中的章节设置不完全一致）。
- 实训基地仓库 [章程写作规范](bylaw.md)。

> 本规范是从既有提案中提取的通用建议格式，具体适用方式及其制度效力待评审确认。

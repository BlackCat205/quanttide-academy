# Issue 编辑

## 流程

1. 强制问询：调用本 skill 后先问用户以下两问，未获答复不得继续
	- 「这件事是否复杂到需要他人协作？简单的活建议自己直接做，不开 Issue」
	- 「目标仓库是哪个？是否已有相关 Issue 或 PR？」
2. 查重：在目标仓库搜索已有 Issue，重复则在原 Issue 下补充，不新开
3. 范围检查：一个 Issue 只对应一个独立功能或问题；多个功能拆成多个 Issue，禁止一次提交一堆
4. 写标题：按下方「标题」格式，一句话、60 字符内、不加句号，说清要解决的问题或要做的功能
5. 按模板逐段写正文：材料只来自用户已说出的信息或仓库现状，查不到的保留占位，不猜测填写
6. 排版遵循 `markdown-editor`，对照验收清单自检后提交

## 标题

```text
<type>(<scope>): <简明描述>
```

type 与 `pr-editor` 一致，只用 feat、fix、docs、style、refactor、perf、test、chore、ci、revert；scope 为模块或领域，可省略。Issue 编号由平台生成，不写进标题。  

- 正确：`feat(skills): 新增 issue-editor 规范 Issue 撰写`
- 错误：`有个问题`、`求助`、`Bug`

## 模板

````markdown
### 背景

2–3 句说清现状和要解决的问题；Bug 写复现步骤、期望结果与实际结果。

### 目标

要做成什么样，只写一个独立功能或问题。

### 验收标准

- [ ] 可检查的完成条件，每条一行

### 关联

仅有相关 Issue、PR 或 roadmap.md 任务时写，没有就不写这段，如 `Related to #123`。
````

## 验收清单

- [ ] 已问询用户是否需要协作、目标仓库与已有 Issue 或 PR，并获答复
- [ ] 已查重，无重复 Issue
- [ ] 一个 Issue 只含一个独立功能或问题
- [ ] 标题为约定式格式，一句话、60 字符内、无句号
- [ ] 背景 2–3 句；Bug 已写复现步骤、期望结果与实际结果
- [ ] 验收标准为复选框，每条可检查
- [ ] 模板内各段大标题为三级标题
- [ ] 关联仅在有相关 Issue、PR 或任务时写入
- [ ] 未编造用户未说出的需求或信息
- [ ] 标题、段落、列表、代码块之间各留 1 个空行
- [ ] 全文小于 150 行

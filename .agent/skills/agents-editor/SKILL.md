# AGENTS.md 编辑

## 流程

1. 通读项目全部文件，掌握项目全貌
2. 一次性问询用户各选填节是否生成，未确认的选填节不生成
3. 按模板逐节顺序填写；查不到的信息保留占位，不猜测填写
4. 对照验收清单自检，全部通过后落盘

## 模板

````markdown
# AGENTS.md

文首 1–2 行（必填）：本文定位、冲突时的优先级与业务规则的单一真源、开发与交付形态（如单人开发、直推 main）。

## 项目概述（必填）

总结项目是什么，不超过三行。

## 相关文档（必填）

README、CHANGELOG 等入口链接，用相对路径。

## 快速定位（选填）

捕捉用户对话中的触发关键词和近似关键词，快速定位项目文件及其锚点内容。同一问题被问过两次才加一行，表越长检索越慢。顿号相连的关键词共用该行锚点，分号隔开的多处锚点都要读；锚点用原文标题，子标题写在括号内。示例如下：

| **关键词** | **文件** | **锚点** |
| :--- | :--- | :--- |
| xx | [xx.md](<xx.md>) | 原文文本/标题 |

## 业务意图（必填）

总结项目业务意图，不超过三行。

## 关键决策（必填）

总结项目关键决策，以有序列表列出，每条为「**加粗短标签**：一句话结论与理由」，不超过 5 条。

## 管道逻辑（选填）

以 mermaid 语法简单概括项目核心模块和产出的数据流向。

## 技术栈（选填）

按层分组（如运行时、数据、质量）总结主要技术栈，不超过 5 个，精确到主版本号。

## 项目目录（必填）

简单树目录，不全部展开，只列关键文件和文件夹并标注职能，示例如下：

```text
项目名/
├── README.md
├── AGENTS.md
├── docs/                    # 项目文档
│   └── xxx/                 # xxx
└── .agent/
    └── skills/              # Agent 工作所需 skill 与脚本
```

## 关键文件（选填）

列出关键文件，不超过 5 条，示例如下：

| **文件** | **职能** |
| :--- | :--- |
| [xx.md](<xx.md>) | xxx |

## 常用命令（选填）

列出开发、测试、质检阶段的重要命令，不超过 5 条；含一组「修改验证」命令，供验证清单引用。

## 核心原则（必填）

只放影响 AI 行为的指令，缺了会做错、或必须遵守的刚性规则。以下为固定规则，可根据项目需求扩展，但总数不超过 10 条：

- 最小干预：仅在用户明确请求时改文件，不主动超出更改范围改无关文件
- 用到再建：除本树已有路径和 README、AGENTS.md 这类根契约外，不创建未使用的（代码）文件或目录
- 结构同步：改名、移动或变更目录后，README、本文快速定位表与内部链接必须同一轮改完
- 技能优先：动手前先查已有 skill 和工具；已有 skill 或工具能做的，禁止另写脚本
- 最大兼容：优先 GFM / CommonMark / LaTeX，不用编辑器私有语法
- 信息复用：不把项目中某文件正文抄进其他文件，采用相对链接

## 常见任务（选填）

项目中高频重复的具体操作（如发布、新建文档）。简单任务写成一行链路（如「确认需求 → 写测试 → 实现 → 验证」）；步骤多的每个任务一个三级标题，示例如下：

### xxx

1. 每步一行，简短精炼
2. 

## 工作流程（必填）

AI 在本项目接到任何任务时的通用步骤，编号有序列表，每步一句话，简短精炼。每步写明触发条件，未触发则跳过；已触发的步骤须做完全部子步才进入下一步，禁止跳步、并步。末步为验证，按验证清单逐条核对，失败不得继续。

## 安全约束（必填）

以下为固定规则，可根据项目需求扩展，但总数不超过 5 条：

- 禁止读取 `.env` 等密钥文件内容，禁止把密钥、口令、令牌写进仓库文件、日志或协作材料（设计、截图、视频、任务页）
- 用户明确要求时才提交或推送
- 只改用户明确提到的工作范围内的文件；范围外的文件须先征得用户同意再改
- 用户有决定权的文件（如路线图、需求基线）禁止擅自修改或打勾

## 验证清单（必填）

复选框，与工作流程编号一一对应，覆盖关键产出物，全部通过才算完成。能用命令验证的写明命令和通过标准（如测试覆盖率 ≥80%）。

- [ ] 
````

## 验收清单

- [ ] 已一次性问询全部选填节，仅生成用户确认的选填节
- [ ] 已按模板逐节顺序填写，必填节均已写入
- [ ] 文首已写明本文定位、冲突优先级与单一真源
- [ ] 项目概述、业务意图均不超过三行
- [ ] 相关文档用相对路径
- [ ] 快速定位若生成，为关键词 / 文件 / 锚点三列表，锚点与原文标题一致
- [ ] 关键决策为有序列表，每条带加粗短标签，且不超过 5 条
- [ ] 管道逻辑若生成，用 mermaid 概括核心模块和数据流向
- [ ] 技术栈若生成，按层分组，不超过 5 个，并精确到主版本号
- [ ] 项目目录为代码块中的简单树，未全部展开，关键文件和文件夹已标注职能
- [ ] 关键文件、常用命令若生成，各不超过 5 条
- [ ] 核心原则只放刚性规则，已包含固定规则，扩展后不超过 10 条，无示例残留
- [ ] 常见任务若生成，仅含高频重复操作
- [ ] 工作流程为编号有序列表，每步一句话并写明触发条件，无冗余
- [ ] 安全约束已包含密钥、提交、改动范围、决定权四条固定规则，且不超过 5 条
- [ ] 验证清单为复选框，与工作流程编号一一对应，覆盖关键产出物，可命令验证的已写命令与通过标准
- [ ] 无法确认的条目已保留占位，未猜测填写
- [ ] 内部链接指向已存在的文件
- [ ] 生成的 AGENTS.md 全文小于 150 行
